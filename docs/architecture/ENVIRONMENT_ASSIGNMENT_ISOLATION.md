# Environment assignment isolation\n\n## Ownership\n\nNoetrium owns the provider-neutral lifecycle contract:\nEnvironmentAssignmentIdentity identifies one assignment and\nEnvironmentAssignmentIsolationPort prepares/finalizes an isolated\nenvironment instance and returns a durability-bearing isolation receipt.\n\nNoetrium does not decide whether a scientific task succeeded. It owns\nlifecycle, identity, recovery, storage, and provider binding.\n\nConcrete providers own the isolation mechanism:\n\n- Minecraft uses world cuts, branch workdirs, server lifecycle, endpoint binding, and action recovery.\n- GUI/Web/Software/Text World providers may use browser profiles, containers, repositories, or process sandboxes.\n- A provider must not reuse a mutable global session for two assignments.\n\nDownstream research owns scientific assignment selection, method policy, task\ngoals, success predicates, metric definitions, benchmark mapping, and claim\nstatus. It may consume the generic isolation port, but must not reimplement\nprovider state restoration inside scientific task logic.\n\n## Branch materialization is not one mechanism\n\nSearch methods need more than one truthful branch strategy. Noetrium therefore\nkeeps three different contracts instead of pretending that all branches are\nsnapshots:\n\n1. **Assignment isolation** prepares/finalizes an independent scientific\n   assignment. Its receipt says nothing about search-tree parent state.\n2. **Snapshot fork** uses `fork_environment_session`: a provider-owned opaque\n   checkpoint from a parent session is restored into a distinct child. The fork\n   receipt binds the checkpoint digest and source cut. It does not make the\n   platform the environment state owner.\n3. **Fresh reset + prefix replay** uses `replay_environment_prefix`: composition\n   opens a fresh session already bound by the provider/caller to the frozen task\n   initial cut and submits an explicit ordered tuple of `ActionRequest` values.\n   Its receipt proves which semantic requests were accepted in order.\n\nReset+replay is deliberately weaker than snapshot restore. It does **not** claim\nhidden-state equivalence, deterministic provider internals, crash durability, or\nexactly-once execution. Methods such as browser tree search may legitimately use\nit when the original implementation reconstructs a branch by resetting and\nreplaying committed actions. Providers that can truthfully restore an exact\ncheckpoint should use snapshot fork when that is the required scientific\nsemantics.\n\nNeither composition helper stores authoritative environment state. Environment\nstate remains provider-owned; Machine/Journal records accepted scientific\nexecution truth and receipts/evidence refer to the relevant source cuts.\n
